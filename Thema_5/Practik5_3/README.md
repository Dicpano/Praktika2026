# Практична робота 5.3 — Дашборд оперативного огляду обстановки

**Тема 5. Методологія відображення даних в інтересах ІАЗ**
**Заняття 3. Практичне використання інструментів візуалізації даних**

Обраний варіант: **Варіант 7 — «Побудова дашборду оперативного огляду обстановки»**
(з елементами варіантів 1, 2, 3, 4, 5, 6 — інтегровано 6 візуалізацій замість мінімально вимогуваних 3–5, як розширення завдання).

---

## 1. Короткий опис завдання

Інтегрувати кілька видів візуалізацій (карта подій, часовий ряд, структура сил, таблиця подій)
у єдиний дашборд оперативного огляду обстановки, придатний для швидкого сприйняття командуванням.

## 2. Характеристика вихідних даних

Використано **синтетичні (умовні) дані** (файл `data.js`), що імітують типовий формат
даних штабної аналітики:

| Набір даних | Формат | Призначення |
|---|---|---|
| `timeSeries` | часовий ряд, 14 діб × 4 напрямки | динаміка атак |
| `enemyStructure` | категоріальні частки, % | структура сил противника |
| `readiness` | 5 параметрів × 3 підрозділи | оцінка боєздатності |
| `correlation` | матриця 5×5 | кореляція факторів втрат |
| `network` | вузли/ребра | J-структура підпорядкування |
| `mapEvents` | x,y (умовні %) + тип/час | подієва карта |
| `eventsTable` | список подій | журнал подій |

Дані перевірено на повноту (пропусків немає, оскільки згенеровані свідомо консистентними)
і приведено до єдиного формату (масиви об'єктів JS) для прямого використання в Chart.js/SVG.

## 3. Обраний тип візуалізації — обґрунтування

| Візуалізація | Тип | Чому саме він |
|---|---|---|
| Динаміка атак | лінійний графік | найкраще показує тренд і піки в часі |
| Структура сил | donut-діаграма | компактно показує частки категорій, % |
| Порівняння напрямків | стовпчикова діаграма | пряме порівняння сумарних значень |
| Readiness | радар-чарт | одночасне порівняння 5 параметрів по 3 об'єктах |
| Кореляція факторів | теплова карта | стандартний спосіб показати силу/напрям зв'язку |
| J-структура | мережевий граф | показує ієрархію та канали інформаційних потоків |
| Карта подій | схематична карта з маркерами | локалізація подій відносно лінії фронту |

## 4. Побудований дашборд

Реалізовано як `index.html` + `style.css` + `main.js` + `data.js` (відкривається у браузері,
зручно запускати через розширення **Live Server** у VS Code). Дашборд містить:
KPI-картки з лічильниками, 6 візуалізацій, журнал подій, блок аналітичних висновків.

## 5. Аналітичні висновки (3–5)

1. Найвища активність — **Східний напрямок** (пік 33 атаки/добу 12.09), стійке зростання з 05.09.
2. У структурі сил переважає піхота (42%) у поєднанні з БПЛА-розвідкою (13%) — ознака підготовки штурмових дій.
3. **2-й БТГр** має знижені показники забезпечення (65%) — пріоритет для поповнення.
4. Інтенсивність атак сильно обернено корелює з відстанню до переднього краю (r = −0.61) — очікувано.
5. Мережевий граф показує, що J3 (операції) — центральний вузол з найбільшою кількістю зв'язків; його втрата найбільш критична для керованості.

## 6. Рекомендації

- Посилити протидію БПЛА на Східному напрямку.
- Перерозподілити резерви забезпечення на користь 2-го БТГр.
- Забезпечити резервний канал зв'язку в обхід J3 на випадок втрати вузла.

## Технічна структура проєкту

```
dashboard/
├── index.html         # розмітка дашборду
├── style.css          # військова стилістика (олива), анімації
├── data.js            # синтетичні дані
├── main.js            # рендер графіків/карти/мережі/теплокарти
├── vendor/
│   └── chart.umd.js   # Chart.js, локальна копія (працює офлайн)
└── README.md          # цей звіт
```

**Запуск у VS Code:** відкрити папку → розширення *Live Server* → «Open with Live Server»
на `index.html`. Chart.js підключається локально з `vendor/chart.umd.js`, тому дашборд
працює навіть без інтернету; онлайн потрібен лише для шрифту Google Fonts
(`fonts.googleapis.com`) — якщо мережа його блокує, шрифт просто замінюється на системний,
решта дашборду не постраждає.

> **Якщо графіки все одно порожні:** відкрий інструменти розробника в браузері (F12) →
> вкладка Console — там буде видно точну помилку. Найчастіша причина — файл відкрито
> подвійним кліком (`file://...`) замість Live Server: тоді браузер блокує завантаження
> `data.js`/`main.js` як модулів із сусідньої папки. Завжди запускай через Live Server
> (`http://127.0.0.1:5500/...`), як у тебе на скріншоті.

## Що покращено відносно базового шаблону (`project/`, `sample1/`)

- Замість плейсхолдерів — 6 повноцінних інтерактивних візуалізацій замість 1 графіка/карти.
- Військова колірна гама (олива + пісочний + жовтий акцент + NATO-блакитний) замість Tailwind-дефолту.
- Анімації: живий годинник, лічильники KPI, «малювання» графіків при завантаженні,
  пульсуючі маркери подій на карті, радар-розгортка та рухома сітка на фоні, «біжуча» лінія сканування.
- Оригінальний SVG-шеврон підрозділу (умовний, не копіює жодну реальну офіційну емблему) з пульсуючим світінням.
- Мережевий граф і теплова карта кореляцій, яких не було в жодному з прикладів.
- Схематична (умовна) карта подій замість реальних тайлів — свідоме рішення: точні геокоординати
  реального фронту є чутливою інформацією, тому картку зроблено як навчальну умовну сітку.

## Обмеження та подальші кроки (самокритика)

- **Відео:** реальне військове відео не вбудовано — по-перше, з міркувань авторського права
  (готові відеоролики з інтернету майже завжди захищені), по-друге, автовідтворення важкого
  відеофону погіршує продуктивність і читабельність панелі керування. Замість цього використано
  легкі CSS/SVG-анімації (радар, сітка, сканування), які дають той самий ефект «живого» інтерфейсу
  без цих недоліків. За потреби відео можна додати самостійно: покласти файл `bg.mp4` в папку
  проєкту і додати `<video autoplay muted loop src="bg.mp4">` у `#battle-bg` з `opacity:0.15`.
- **Шеврон:** використано узагальнений оригінальний символ (не офіційна емблема конкретної бригади) —
  за потреби замінити на офіційний шеврон реальної частини (SVG/PNG у `img/`) і підставити в `index.html`.
- **Карта:** для реальних географічних даних варто підключити Leaflet + офлайн-тайли
  (у польових/захищених мережах онлайн-тайли OpenStreetMap можуть бути недоступні або небажані
  з міркувань OPSEC).
- **Дані:** усі числові показники — синтетичні; для реального використання потрібен імпорт
  з реального CSV/API (структура `data.js` вже сумісна — досить замінити вміст об'єкта `DASHBOARD_DATA`).
- **Продуктивність:** при великих обсягах подій (>200) варто перейти з малювання маркерів у DOM
  на `<canvas>`-рендер карти.
