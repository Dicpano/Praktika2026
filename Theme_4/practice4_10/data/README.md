# Data card — sensor_data.csv

| Поле | Значення |
|---|---|
| Джерело / provenance | synthetic; генерується `src/pipeline.py::generate_sensor_data(cfg)` з `config.json` (`seed=42`) у notebook `01_data.ipynb` |
| Ліцензія / дозволи | власні згенеровані дані, обмежень немає |
| Чутливість | немає: не містить реальних, персональних чи службових даних |
| Період | 2026-01-01 — 2026-04-30, крок 10 хв |
| Обсяг | 17 280 рядків × 6 стовпців (≈1.6 МБ) |
| Схема | `timestamp` (datetime), `temperature` (°C), `vibration` (умовні од.), `pressure` (кПа), `label` (0/1), `atype` (тип аномалії або порожньо) |
| Мітки | точкові; вікно вважається аномальним, якщо містить ≥1 аномальну точку |
| Аномалії | 70 подій, 8.1% точок: `spike` (1–3 точки, 4–6σ), `level_shift` (12–36 точок, 1–1.6σ), `vib_oscillation` (18–36 точок), `decorrelation` (24–48 точок, тиск не залежить від температури) |

## Модель генерації нормальної поведінки
- `temperature = 20 + 5·sin(добова фаза) + N(0, 0.4)`; у test-періоді додано лінійний дрейф до +1 °C;
- `pressure = 100 + 0.8·(temperature − 20) + N(0, 0.3)` — фізичний зв'язок із температурою;
- `vibration = 1 + 0.1·sin(3·добова фаза) + N(0, 0.15)`.

## Обмеження
- Синтетичні сигнали простіші за реальні: немає пропусків, рідкісних режимів роботи та сезонності довшої за добу.
- Аномалії мають відомі заздалегідь типи. На реальних даних можуть траплятися нові типи.
- Частка аномалій у validation (13% точок) вища, ніж у test (8%). Через це поріг, підібраний на validation, може бути трохи заниженим для test.
